# Descripcion
Why use p and q when I can use more?
## Solución

El reto "b00tl3gRSA3" usa **RSA multi-primo**: en lugar de solo dos primos $p$ y $q$, el módulo $N$ es el producto de muchos primos. Esto hace que $\phi(N)$ sea diferente, pero el esquema de descifrado sigue siendo el mismo una vez conocemos los factores.

**Proceso:**

1. **Conexión al servidor** (`nc chatelaine.cylabacademy.net 17502`):

   - El servidor devuelve $c$, $N$ y $e = 65537$.

2. **Factorización de $N$**:

   - $N$ tiene **1142 bits** pero está compuesto por **34 primos de ~34 bits** cada uno (mucho más pequeños que los 512 bits recomendados por primo).

   - Usando el algoritmo de **Pollard's rho**, factorizamos $N$ en ~1 segundo, obteniendo los 34 factores primos.

3. **Cálculo de $\phi(N)$ generalizado**:

   - Para RSA multi-primo: $\phi(N) = \prod_{i=1}^{k}(p_i - 1)$

   - Con los 34 primos conocidos, calculamos $\phi(N)$ directamente.

4. **Descifrado RSA estándar**:

   $$d = e^{-1} \pmod{\phi(N)}, \quad M = c^d \pmod N$$

  import math, random

  def pollard_rho(n):

      if n % 2 == 0: return 2

      x = random.randint(2, n-2)

      y, c, d = x, random.randint(1, n-1), 1

      while d == 1:

          x = (x*x + c) % n

          y = (y*y + c) % n

          y = (y*y + c) % n

          d = math.gcd(abs(x-y), n)

      return d if d != n else None

  def is_prime(n, k=20):

      if n < 2: return False

      if n == 2: return True

      if n % 2 == 0: return False

      r, d = 0, n-1

      while d % 2 == 0: r += 1; d //= 2

      for _ in range(k):

          a = random.randrange(2, n-1)

          x = pow(a, d, n)

          if x in (1, n-1): continue

          for _ in range(r-1):

              x = x*x % n

              if x == n-1: break

          else: return False

      return True

  def factorize(n):

      if n <= 1: return []

      if is_prime(n): return [n]

      d = None

      while d is None or d == n: d = pollard_rho(n)

      return factorize(d) + factorize(n // d)

- **Vulnerabilidad**: La debilidad proviene de que cada primo individual (≈34\approx 34≈34 bits) es demasiado pequeño para RSA seguro. La factorización de enteros de 34 bits es trivial. RSA requiere primos de **al menos 1024 bits** cada uno para ser seguro.
- **RSA Multi-primo legítimo** (RFC 3447): Existe una variante legítima llamada _Multi-prime RSA_ que usa 3 o más primos, pero todos ellos deben ser lo suficientemente grandes (~512 bits cada uno).
