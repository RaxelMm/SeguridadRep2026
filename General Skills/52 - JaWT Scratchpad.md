# Descripcion
Check the admin scratchpad!
## Solucion
1. **Análisis Inicial:** Se inició sesión en la aplicación web con un usuario genérico (`carlos`). Al revisar las herramientas de desarrollo del navegador (`F12`), se identificó que la sesión se gestionaba a través de una cookie llamada `jwt`. 2. **Identificación de Vulnerabilidad:** Al decodificar el JWT, se observó que utilizaba el algoritmo `HS256`, el cual es simétrico y depende de una clave secreta en el servidor para firmar los tokens. 3. **Ataque de Diccionario:** Se procedió a realizar fuerza bruta sobre la firma del token utilizando la herramienta `John the Ripper` junto al diccionario `rockyou.txt` mediante el comando: ```bash john jwt.txt --format=HMAC-SHA256 --wordlist=/usr/share/wordlists/rockyou.txt ``` La herramienta reveló exitosamente la clave secreta del servidor: `ilovepico`. 4. **Falsificación de Token (Privilege Escalation):** Con la clave secreta expuesta, se utilizó el sitio `jwt.io` (o un script personalizado) para modificar el campo `"user"` en el Payload de `"carlos"` a `"admin"`. Posteriormente, se firmó el nuevo token usando la clave `ilovepico`. 5. **Explotación:** Se reemplazó el valor de la cookie `jwt` en el navegador con el token falsificado a través de las herramientas de desarrollador y se recargó la página (`F5`). El backend validó la firma falsa, otorgando acceso al bloc de notas del administrador, donde se visualizó la bandera (`picoCTF{...}`).
## Notas Adicionales
* **Debilidad en la Firma:** El éxito de este ataque radica exclusivamente en el uso de una clave secreta extremadamente débil y predecible. Si el servidor hubiese implementado una contraseña robusta o criptografía asimétrica (como RS256), el ataque de diccionario habría fallado. * **Persistencia de Cookies:** Al modificar cookies de forma manual mediante extensiones o la consola, es crucial asegurarse de no dejar espacios o saltos de línea al final del string del JWT, ya que el navegador o el software de la extensión pueden rechazar el cambio silenciosamente.
