# Descripcion
In RSA d is a lot bigger than e, why don't we use d to encrypt instead of e? Connect with nc xebec.cylabacademy.net 23824.
## Solución

El reto "b00tl3gRSA2" invierte los roles del RSA clásico: **usa $d$ para cifrar en lugar de $e$**. El servidor nos da $c$, $n$ y lo que llaman "$e$" (que en realidad es el exponente grande, equivalente a $d$ en RSA estándar).

**Razonamiento:**

- En RSA normal: se cifra con $e$ pequeño (ej. 65537), se descifra con $d$ grande.

- En esta versión "bootleg": se cifra con $d$ grande, se descifra con $e$ pequeño.

- El servidor llama "$e$" al exponente grande que usó para cifrar. Para descifrar, necesitamos el verdadero $e$ pequeño, que es el valor estándar: **$e = 65537$**.

El descifrado es simplemente:

$$M = c^{65537} \pmod{N}$$

## Notas Adicionales

- **Script Python**:

  python

  c = 4789630397308693...   # del servidor

  n = 9089167013997123...   # del servidor

  # El 'e' dado es enorme (~1023 bits), es el exponente de cifrado (el d invertido)

  # Para descifrar, usamos el e estándar pequeño

  m = pow(c, 65537, n)

  hex_str = hex(m)[2:]

  if len(hex_str) % 2: hex_str = '0' + hex_str

  print(bytes.fromhex(hex_str).decode())

- **Por qué es inseguro**: En RSA, la seguridad del cifrado radica en que eee (el exponente de cifrado, conocido por todos) sea pequeño y estándar, mientras que ddd (el exponente de descifrado) se mantiene secreto. Invertir los roles hace que el "exponente secreto" (e=65537e = 65537e=65537) sea predecible y estándar, rompiendo toda la seguridad del esquema.
- **Nota**: El valor "e" que muestra el servidor en este reto es en realidad el ddd privado del sistema RSA original, y el verdadero eee (con el que se descifra) es el público y conocido `65537`.
